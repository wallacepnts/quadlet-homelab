A Windows VM you open in the browser. Nothing is installed on the host.

Web viewer on **8006**, RDP on **3389**. Unit `vm-windows`.

The install asks which Windows to put in — nineteen options, from Windows 11 Pro down to XP, ReactOS and the trimmed Tiny11 builds. The image is downloaded from Microsoft's own servers on the first boot and takes a while; the browser viewer shows the whole installation.

Changing `VERSION` afterwards does nothing: the disk is already written. To switch, remove the volume and start over.

The account inside Windows is `Docker`, and its password is a generated secret — the install prints it. It is what RDP on 3389 asks for; the browser viewer asks for nothing.

`vm-windows-arm` publishes the same ports on purpose. They are alternatives — one for an x86 host, one for ARM — and only one runs at a time.

All of these need `/dev/kvm` on the host — without hardware virtualisation
the VM either refuses to start or crawls. `RAM_SIZE` is reserved for the whole
life of the VM, so leave the host enough to breathe; `DISK_SIZE` is a ceiling
and grows on demand.

## Install

```bash
qh vm-windows
qh vm-windows --apply
```

Installing the folder — `qh vm --apply` — brings this one along with the rest.

## Systems

The install asks, and writes the answer to the `.env`. It only matters on the
first boot: the image is downloaded once, and changing the value later does
nothing to a disk already written.

## Files

```
vm-windows.container     unit
vm-windows.env.example   environment
```

Data in `~/.config/containers/volumes/vm/windows/storage`, `~/.config/containers/volumes/vm/windows/oem`, `~/.config/containers/volumes/vm/windows/shared`.

Its password is the secret `vm-windows-password`, generated by the install.

## Update

```bash
qh vm-windows --update --apply
```

Pinned to `6.04`. Nothing updates on its own — a new version is applied when
you run the command above.

## Backup

```bash
qh vm-windows --backup --apply --out ~/backups
```

The archive holds this unit's directories, its secrets and its own `.env` — nothing a sibling also reads.

It stops this unit, packs it and starts it again. Cold on purpose: copying a
live database gives an archive that only fails when you restore it.

```bash
qh vm-windows --restore ~/backups/vm-windows-20260809-1200.tar.gz --apply
```

Restoring asks you to type `vm-windows` to confirm, because the current data is
deleted before the archive is unpacked.

## Remove

```bash
qh vm-windows --remove --apply           # stops it, keeps the data
qh vm-windows --remove --purge --apply   # and deletes its volume
```

Only the volumes of this VM. `vm-windows.env` is kept even though nothing else
reads it — a per-unit purge does not touch the environment file.

The secret `vm-windows-password` survives a per-unit removal — it is registered with podman,
not inside the volume. `podman secret rm vm-windows-password` is the separate step.
