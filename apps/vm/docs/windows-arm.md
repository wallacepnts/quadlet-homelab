The same as `vm-windows`, built for an ARM64 host.

Web viewer on **8006**, RDP on **3389**. Unit `vm-windows-arm`.

Use this one when the machine running Podman is ARM — a Raspberry Pi 5, an Ampere server, an Apple Silicon Linux. On an x86 host it is `vm-windows` that you want.

It shares 8006 and 3389 with `vm-windows`, which `check.py` is told to allow. Starting both at once fails on the port, and that is the intended outcome: only one of the two makes sense on a given machine.

Fewer editions than the x86 image, because not every Windows was built for ARM.

All of these need `/dev/kvm` on the host — without hardware virtualisation
the VM either refuses to start or crawls. `RAM_SIZE` is reserved for the whole
life of the VM, so leave the host enough to breathe; `DISK_SIZE` is a ceiling
and grows on demand.

## Install

```bash
qh vm-windows-arm
qh vm-windows-arm --apply
```

Installing the folder — `qh vm --apply` — brings this one along with the rest.

## Files

```
vm-windows-arm.container     unit
vm-windows-arm.env.example   environment
```

Data in `~/.config/containers/volumes/vm/windows-arm/storage`.

Its password is the secret `vm-windows-arm-password`, generated by the install.

## Update

```bash
qh vm-windows-arm --update --apply
```

Pinned to `6.04`. Nothing updates on its own — a new version is applied when
you run the command above.

## Backup

```bash
qh vm-windows-arm --backup --apply --out ~/backups
```

The archive holds this unit's directories, its secrets and its own `.env` — nothing a sibling also reads.

It stops this unit, packs it and starts it again. Cold on purpose: copying a
live database gives an archive that only fails when you restore it.

```bash
qh vm-windows-arm --restore ~/backups/vm-windows-arm-20260809-1200.tar.gz --apply
```

Restoring asks you to type `vm-windows-arm` to confirm, because the current data is
deleted before the archive is unpacked.

## Remove

```bash
qh vm-windows-arm --remove --apply           # stops it, keeps the data
qh vm-windows-arm --remove --purge --apply   # and deletes its volume
```

Only the volumes of this VM. `vm-windows-arm.env` is kept even though nothing else
reads it — a per-unit purge does not touch the environment file.

The secret `vm-windows-arm-password` survives a per-unit removal — it is registered with podman,
not inside the volume. `podman secret rm vm-windows-arm-password` is the separate step.

## Commands

```bash
systemctl --user status vm-windows-arm
podman logs -f vm-windows-arm
qh vm-windows-arm --update --apply
```
